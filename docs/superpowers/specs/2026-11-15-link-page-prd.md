# Wishwell 链接页 PRD (transcribed 2026-11-15)

Source: team PRD doc "Wishwell 链接页 PRD" (Nov 15, 2026).

## 目标与范围
链接页让没装 App 的人，在微信、iMessage 或 IG 里点开朋友推来的纸船后，30 秒内许一个自己的愿、并把这只纸船认领或推下去。
- 谁会收到：只有被朋友推了纸船的人。纸船可能来自朋友的真实愿望，也可能是朋友推来的今日纸船；对收到的人来说没有区别，只是卡片上的标签不同。
- 只有一种链接：用朋友的背书让他愿意打开，用免费愿望让他愿意完成。
- 核心机制：先写自己的免费愿望，再处理手上的纸船；处理完成的那一刻，他的愿望出发。
- 不需要下载 App、不需要注册。只在最后留一个联系方式，用来发靠岸通知。

## 用户旅程（6 步，只有第 4 步有分支）以 Amy 把 Louise 的纸船推给 Ben 为例
1. 收到消息：Ben 在微信里看到 Amy 发来的链接，预览是"Amy：你身边有很多做设计的朋友，帮我看看这个？她还送了你一个免费愿望 🪙"。
2. 打开第一屏：看到 Amy 对他的背书、纸船上的愿望（Louise 想认识一个从 pre-med 转去做设计的人）、已漂几跳和剩余时间。点"领取你的免费愿望"。
3. 写自己的愿望：一行字，AI 润色。写完提示"让它出发：帮 Amy 处理这只纸船"。也可以点"先不许，只帮忙"跳过。
4. 处理纸船（二选一）：
   - 我就是：写一句自我介绍。今日纸船拍一张证明照；真实愿望回答 AI 的 1 到 2 个问题，并做手机验证。
   - 推给一个人：AI 用问题帮他想到一个人 → 点选关系和推荐理由，AI 合成一句背书 → 打开分享面板，用微信或 iMessage 发出。
5. 留联系方式（必填）：手机号或邮箱，"你的愿望靠岸时，我们通知你"。
6. 完成屏："你的愿望出发了" + 预言 + 进度 ●○○○○ "再推 4 只纸船就能再许一个愿" + 下载 App。

之后：纸船或愿望靠岸时，Ben 收到一条短信，点开是结局页。如果他认领了真实愿望并被确认，系统直接用短信把双方的手机号发给对方，不需要下载 App。
跳过许愿的人直接进入"处理纸船"；两条分支最后都要留联系方式，认领真实愿望的人被确认后，系统用短信帮双方交换手机号。

## 页面与功能需求（6 个屏幕，第一屏不滚动就能看到主按钮）
| 屏幕 | 内容 | 验收标准 |
|---|---|---|
| 消息预览（OG 卡片） | 推纸船的人对你的背书 + "还送了你一个免费愿望" | 在微信、iMessage、IG 里都能正确显示标题和图 |
| 1. 第一屏 | 背书（最上面）；纸船卡片：愿望、来源标签、可展开的背书链、已漂几跳、剩余时间；主按钮"领取你的免费愿望"；底部三步说明 | 1 秒内打开；不登录即可看到全部内容 |
| 2. 写愿望 | 一行输入框 + AI 润色；"先不许，只帮忙"跳过入口 | 润色 3 秒内返回；未完成时草稿保存在本地 |
| 3a. 认领 | 自我介绍；今日纸船：证明照 + 是否允许展示名字和城市；真实愿望：AI 追问 + 手机验证码 | 认领后状态显示"等待许愿者确认" |
| 3b. 推给一个人 | AI 回忆提示；输入对方名字；点选关系 + 推荐理由 → AI 生成背书；打开系统分享面板 | 生成一个新的唯一链接；背书可修改 |
| 4. 留联系方式 | 手机号或邮箱二选一 | 必填；不填不能进入完成屏 |
| 5. 完成屏 | "你的愿望出发了" + 预言 + 进度 ●○○○○ + 下载 App 按钮 | 进度和愿望绑定在留下的联系方式上，下载 App 后自动同步 |
| 结局页（短信链接） | 合照或证明照、两句故事、路线、分享拍立得、下载 App | 无需登录即可打开 |

## 规则与特殊情况
一个链接只对应一只纸船、一个收件人；认领或推出去，都算完成任务并让免费愿望出发。
规则：
- 每次只推给 1 个人；背书写的是下一个人。
- 每个链接访客只有 1 个免费愿望（按联系方式去重）；之后的愿望按"5 只纸船换 1 枚硬币"累计。
- 写了愿望但没处理纸船：愿望保存为草稿，如果留了联系方式，24 小时后提醒一次"你的愿望还在岸边等着出发"。
- 分享文案只描述愿望和背书，不写"转发才能…"，避免被微信判定为诱导分享。

特殊情况：
| 情况 | 页面显示 |
|---|---|
| 纸船已经被别人认领 | "这只纸船已经找到人了" + 结局预览 + 免费愿望入口 |
| 纸船已过期（48 小时） | "这只纸船没能靠岸" + 免费愿望入口 |
| 已经处理过这个链接 | 显示他的选择和纸船现在漂到了哪里 |
| 已经用过免费愿望 | 跳过写愿望步骤，直接处理纸船；完成屏显示累计进度 |
| 想推给自己或推回上游 | 不允许，提示换一个人 |
| 链接被转给了其他人 | 其他人也能打开，但页面提示这只纸船是推给 Ben 的，并引导他领取自己的免费愿望 |

## 下载引导、通知与指标
网页负责"做"，App 负责"看"和"继续"。只在三个时刻引导下载，从不阻挡核心动作。
| 时刻 | 文案 | 是否必须下载 |
|---|---|---|
| 完成屏 | "再推 4 只纸船，就能再许一个愿" | 否 |
| 结局页 | "下载 App，看你推过的所有纸船漂到了哪里" | 否 |
| 真实愿望的认领被确认后 | "Louise 确认了，就是你！我们已经把她的手机号发给你，也把你的发给了她" | 否：交换联系方式不需要 App，确认后用短信把手机号直接发给对方，合照通过短信里的链接上传 |

短信/邮件通知只有三种：靠岸回执（你推的纸船被认领了）；结局解锁（合照上传了，点开看结局）；你的认领被确认（仅真实愿望），短信里附上对方的手机号。

指标：打开率、许愿率、完成率（最核心）、跳过率、留资率、下载率（链接访客 7 天内下载 App 的比例）。
Hackathon 要测的：完成率，以及"先许愿"是否让完成率更高（对比写了愿望和跳过的人）。
